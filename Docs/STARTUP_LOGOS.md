# Startup logo interception

The startup sequence is in loading_screen.gfx / loading_screen_jp.gfx inside the stored ZIP entry [gfx]/gfxbundle.gfxbundle. The constructor registers the ready frame after the warning; StartSkippables schedules publisher logos before OnAllAnimFinished. Two equal-length ActionScript changes per locale keep initialization on frame 2, move the ready callback to frame 3, and call OnAllAnimFinished directly. All timeline callbacks remain registered. The normal startLs transition remains. The transparent-clip experiment blocked progression even after restoring that transition, and was discarded. The loading artwork may briefly appear before the menu. These game-byte locations were checked against the local archive. The public investigation at https://github.com/andizla/snowrunner-next-gen/blob/main/engine/tools/gfx_intro.js provided the timeline/method identification. Its archive-writing implementation is not bundled or used; Enhanced implements a native read-buffer interceptor.

src/startup-profile.json records the supported archive SHA-256, size, original game bytes, replacements and absolute file offsets. tools/build_native.py generates the native header. No game assets are distributed apart from the short byte signatures necessary for compatibility checks.

Initialization is synchronous in InitializeASI before returning control to the game. With the option off no startup hook is installed. With it on, an archive handle opened with GENERIC_READ and FILE_SHARE_READ is hashed and held until process exit to prevent changes after validation. A mismatched archive installs no hook. NtReadFile interception matches volume/file identity, serializes targeted synchronous reads, handles fragments, tracks pending reads by their completion record, and only replaces verified bytes in completed buffers. GetOverlappedResult is intercepted before returning success to the game. Failed and incomplete reads remain unchanged. Both complete methods of either localized movie must have been read before status becomes active. Other files are unchanged.

The archive hash is intentionally strict in this preview. Mapped-file reads and asynchronous completion mechanisms other than GetOverlappedResult are not supported. Their use by a future game build may leave the feature armed; this is not proof of successful skipping. Archive hashing adds startup work. Physical game validation and regression results are recorded separately.

Native test: compile tests/native/startup_host.c with the same build environment and generated headers, then pass the installed Sources/Bin/ directory (with trailing separator). It opens the archive read-only, exercises whole-method, single-byte and overlapped reads, and verifies original bytes through the underlying syscall. It does not launch the game or alter the archive.

## Validation, November 22, 2026

The user confirmed the final frame-3 version opens the menu correctly and asked to keep it. Installed configuration has both enhancements enabled. Earlier transparent-clip attempts were rejected and are absent from the final profile. The original loading artwork/transition remains; the final version does not force an entirely black loading phase.

Automated evidence: 43 installer/compatibility tests, 82 installer UI checks, 541 wheel assertions, ASI loader scenarios, plus full/fragmented/overlapped archive-read tests (four pending completions). The archive SHA-256 was checked unchanged after the game test. Other game archive versions deliberately retain their original startup sequence.
